## 记录规则

- `已确认`：用户已经明确接受，后续讨论以此为前提。
- `待讨论`：已经提出，但范围和行为尚未澄清。

## 访谈推进顺序

执行监督闭环、桌面陪伴、自我成长与知识整理、成长上下文、飞书渠道，以及第一轮平台、进程、AI、费用、凭据、安装更新、每日复盘时间和桌宠素材边界已经完成需求确认。当前进入第一版技术可实施性与收尾阶段，依次验证密码保护备份和迁移方案，补齐剩余运行细节与用户体验事项，最后汇总需求基线、未决验证和后置路线形成实施交接。用户临时补充的新设想仍先归档，不能让已经列出的未决项消失或跳过。

### 第一版平台

第一版唯一正式支持的平台是 Windows 11 64 位，以安装程序安装并提供 `.exe` 应用，首要验收环境是用户当前的 Windows 11 64 位电脑。透明桌面形象、托盘、开机启动、键鼠空闲检测、前台软件识别和本机通知优先在该环境稳定实现。第一版不承诺 Windows 10、Windows on Arm、macOS 或 Linux 兼容；内部模块仍保持清晰边界，等出现分享、商业化或跨设备的真实需求时再扩展平台测试范围。安装程序可以在未支持环境中主动阻止安装或明确提示不受支持，不能把未经测试的“也许能运行”表述为兼容。

### 第一版前端形态

第一版采用桌面前端，不提供需要浏览器打开的网页入口。透明桌宠、提醒气泡、窗口层级、鼠标穿透、托盘、开机启动和 Windows 活动观察由桌面应用承担；对话、设置、承诺编辑、复盘、记忆中心和知识图谱等复杂面板允许在桌面程序内部使用 Web UI 技术，但对用户仍表现为同一个 Windows 应用。内嵌 Web UI 不意味着建设网站，也不要求因此增加云端后端。

第一版实现基线暂定为 `.NET 10 LTS + C# + WPF`。`Jarvis Core` 和 `Jarvis Desktop` 都采用 .NET；桌宠、提醒、聊天、设置、承诺编辑和复盘优先使用 WPF 原生界面，只有知识图谱等确实依赖成熟 Web 组件的复杂页面才按需创建 WebView2，面板关闭时不得让 WebView2 成为无必要的常驻负担。产品以 `win-x64` 自包含方式发布并由 Windows 安装程序封装，用户不需要自行安装 .NET 开发环境。

这项技术栈是可调整的暂定方案，不因写入文档就永久锁定。全面开发前必须先制作最小技术验证原型，在目标电脑上验证透明置顶桌宠、动画、交互区与鼠标穿透区、托盘、命名管道重连、进程故障恢复、多显示器与 DPI、睡眠恢复和安装升级，并执行已经确认的资源验收。只有原型通过才沿用该方案；若简化动画后仍不能满足完整面板关闭时十分钟稳定空闲窗口内合计内存平均不超过 320 MiB、采样峰值不超过 350 MiB、稳定空闲 CPU 平均低于 1% 等基线，则用同一场景制作 Tauri 2 对照原型后重新选型。不能仅凭安装包大小或框架宣传切换技术栈。

### 第一版安装与更新

第一版由一个 Windows 安装包安装两个自包含的程序进程及其依赖。版本更新由用户取得并手动运行新版安装包，不在后台静默下载或安装；公开分发或多用户维护出现真实需求时，再评估内置自动更新渠道。安装包可以检测现有版本并执行原位升级，保留正式数据、设置和当前电脑的 Windows 凭据，但不能把程序文件与用户数据库混成不可分离的单文件状态。

存在正在自动监督的工作承诺时禁止开始升级。Jarvis 提供等待监督结束，或明确停止本次监督后继续两个入口；升级程序不得擅自把监督切成无法观察并继续安装。正式写入新程序或迁移数据库前，Core 必须生成并验证一份升级前密码保护备份，记录旧程序版本和数据库结构版本；备份失败时中止升级，不能让用户跳过这一保护继续覆盖。

升级在安全停止 Core 与 Desktop 后替换程序并执行版本化数据库迁移，随后自动进行启动、数据库打开、结构完整性、核心与桌面连接和只读数据抽样健康检查。第一版在本机保留一个上一版程序副本及对应的升级前回滚副本；健康检查失败时自动恢复上一版程序和升级前数据库，再启动上一版并明确报告回滚结果。故障报告不得包含供应商凭据、备份密码或私人正文。回滚本身失败时停止反复尝试，保留原始备份不变并提供人工恢复入口，不能把部分成功表述为已经恢复。

卸载时必须明确提供“仅移除程序”和“同时删除本机数据”两个选择，默认选择仅移除程序。仅移除程序会停止 Core 与 Desktop、移除程序文件和自启动入口，但保留本机数据库、本地密码保护备份、设置及当前电脑的供应商凭据，重新安装时可以检测并继续使用。卸载界面必须明确列出保留位置，不能用模糊的“保留设置”掩盖私人数据仍在本机。

“同时删除本机数据”是需要二次确认的破坏性操作，删除正式数据库、Jarvis 专用本地备份目录、应用设置、云端请求与费用记录、普通日志、崩溃报告和 Windows 凭据管理器中的 Jarvis 供应商凭据及备份密码。删除前提供生成最终密码保护备份的入口；若用户选择生成，必须让用户保存到本次清理范围之外的位置并验证成功后再继续。用户可以明确放弃最终备份，但界面必须说明本机数据将无法通过重新安装恢复。用户在本机之外自行记录的备份密码不由卸载程序查找或删除。

卸载程序不调用百度网盘 API，也不删除或宣称删除百度网盘云端已有备份；即使选择删除本机数据，也只说明云端文件需要用户在百度网盘中另行检查和处理。存在正在监督的工作承诺时，卸载必须先提示并取得停止监督的明确确认，不能静默结束监督后继续。实际删除前应解析并展示受影响的 Jarvis 专用路径，不能使用未验证的宽泛目录或通配范围。

### 第一版本地后台与数据

第一版的监督核心和 SQLite 数据库都运行在用户的 Windows 电脑上，不建设由项目自行维护的独立云端后端。工作承诺、监督记录、复盘、个人成长档案和知识数据默认以本机数据库为正式数据源；飞书和 AI 模型作为受控外部接口由本地 Jarvis 调用，不因此取得完整本地数据库。只有当前操作必需的数据可以按既定隐私与按来源授权规则发送。跨设备同步、电脑关机后继续服务、手机完整访问历史和多用户账号体系出现真实需求时，再重新评估云端后端。

本机正式 SQLite、WAL、临时文件和升级回滚副本不做 Jarvis 应用层加密，统一放在当前 Windows 用户的应用数据目录并使用正常用户权限。第一版安装设置提示用户为电脑开启 Windows 设备加密或 BitLocker，但不把磁盘加密状态作为启动监督的前提。该边界意味着能够读取当前 Windows 用户文件的人也能直接读取本机数据库；等产品确实长期落盘保存截图、输入文字等更敏感内容，或用户明确提出防止数据库文件被复制读取时，再重新评估应用层数据库加密。

只有会离开当前电脑的百度网盘备份、手动导出和迁移包使用密码保护。用户第一次启用备份时设置一个备份密码并重复确认；Jarvis 可以把它保存在当前电脑的 Windows 凭据管理器中以支持自动备份，新电脑恢复时由用户重新输入。第一版不再生成数据库密钥或独立恢复密钥。忘记密码但本机数据库仍在时，可以设置新密码重新生成备份；本机数据和密码同时丢失时，旧密码保护备份无法恢复。

`Jarvis Core` 在运行期间每天自动生成一次密码保护备份，并在程序升级或数据库结构迁移前额外生成一次；用户也可以随时点击“立即备份”。备份使用成熟标准格式和密码加密能力，不自行设计密码算法或多层密钥封装。生成备份前必须取得一致的 SQLite 快照；完成后自动校验文件可打开、版本可识别且内容完整，失败时通过桌面和托盘明确告警并提供重试。

用户选择百度网盘作为第一版首选灾难恢复位置。Jarvis 只向用户指定的本地备份目录写入密码保护备份，不能向百度网盘同步未保护的数据库副本。用户以后可以更换备份位置，不改变备份文件格式或备份密码。

第一版不直接接入百度网盘 API。首次设置引导用户在已经安装的百度网盘 Windows 客户端中，把 Jarvis 专用本地备份目录添加为自动备份文件夹；百度客户端独立负责登录和上传，Jarvis 不接触百度账号密码或授权令牌。Jarvis 只确认本地密码保护备份的生成与校验结果，不能把它表述为云端上传成功；检测到百度客户端未运行时提示“本地备份已完成，等待网盘上传”，但不因此把本地备份标记为失败。

本地备份目录默认保留最近 30 份每日备份、最近 12 份月度长期备份和最近 3 份程序升级或数据库迁移前备份，数量可以在设置中修改。只有新的密码保护备份通过完整性和版本校验后，才能清理超过本地保留数量的旧文件；清理失败不能影响新备份的成功状态，但需要报告空间问题。第一版不通过 Jarvis 自动删除百度网盘云端旧文件，也不承诺云端保留数量，只定期提示用户检查网盘空间。

生成新备份后，如果连续 24 小时没有检测到百度网盘客户端运行，Jarvis 只在桌宠和核心托盘提醒一次，此后仍未运行时每天最多再提醒一次，不发送飞书。检测到客户端重新运行后，状态只能变为“百度网盘客户端已运行，等待其处理”，不能标记云端上传成功；Jarvis 无法通过第一版集成确认云端文件时，界面必须持续区分“本地已备份”和“云端状态未知”。

设置中提供用户主动触发的“测试备份”与“恢复备份”入口；测试恢复到隔离临时位置且不覆盖正式数据库。第一版不要求首次设置或每六个月进行强制恢复演练，日常只依靠每次备份的自动校验和用户按需测试。更换备份密码后，新备份使用新密码；旧备份仍需要原密码，Jarvis 必须在更换前明确提示。

本机程序采用两个普通用户进程：`Jarvis Core` 负责监督状态机、活动观察、计时、SQLite、飞书和 AI 编排，`Jarvis Desktop` 负责桌宠、气泡、对话、设置及其他可见界面。两者由同一安装包安装并作为一个产品启动；桌面进程隐藏、重启或崩溃时，核心监督可以继续。`Jarvis Core` 运行在当前 Windows 用户会话中，不注册为高权限 Windows 系统服务，也不以管理员权限作为正常监督的前提。

监督采用“AI 增强、确定性监督核心保底”的边界。工作承诺生效、活动分类规则、监督状态转换、计时、休息、提醒升级、记录和既有确认规则都必须在本机不依赖生成式 AI 执行；断网、模型超时、服务故障、额度耗尽或用户暂时关闭 AI 时，这些能力仍应正常运行。AI 负责自然语言理解、闲聊、承诺回顾辅助、记忆提炼和知识整理，也可以提出候选操作，但所有改变承诺或监督状态的操作必须交由确定性监督核心验证。

AI 暂时不可用时，Jarvis 必须明确显示能力降级，保留已经产生的监督事实，并为创建承诺、回应提醒、确认休息、调整承诺和填写回顾提供按钮、表单或模板入口；不能伪装成仍在理解自然语言，也不能因为模型失败而漏计时、漏记录、自动结束监督或擅自执行不确定操作。AI 恢复后可以继续提供增强能力，但不能追溯改写故障期间已经形成的事实记录。

第一版 AI 增强能力默认使用云端模型 API，优先保证自然语言理解、闲聊、承诺回顾和记忆提炼的可用质量；本地模型不作为第一版交付前提，后续用于仅限本机资料、离线对话或降低云端依赖。用户可以关闭云端 AI，关闭后确定性监督核心继续运行，依赖模型的功能明确降级或暂停。资料源已经标记为仅限本机时，在本地模型尚未配置或能力不足的情况下只能说明功能暂不可用，不能静默发送到云端。

Jarvis 从第一版建立模型供应商适配器，不把业务逻辑、记忆格式、监督命令或数据库结构绑定到某一家云端服务。更换供应商必须由用户配置并明确显示当前服务商，继续遵守每个资料源的云端授权和最小发送规则；“接口可替换”不表示模型故障时可以把私人内容无感转发给另一家服务商。具体第一版供应商、模型、费用上限和密钥配置方式继续单独确认。

第一版模型供应商进入有退出条件的两周试运行：通过用户自己的硅基流动账号调用 DeepSeek V4，日常闲聊使用 `deepseek-ai/DeepSeek-V4-Flash` 的非思考模式；自然语言候选操作、每日/周期复盘辅助、复杂原因归纳和跨资料知识综合等复杂任务使用 `deepseek-ai/DeepSeek-V4-Pro`。模型路由由本机依据已确认任务类型执行，AI 不能自行把普通请求升级到 Pro，也不能借此绕过费用和资料授权。

阿里云百炼 `qwen3.7-flash` 只作为同一组脱敏 Jarvis 提示词的隐私、稳定性、结构化输出、中文陪伴和费用对照，不在 DeepSeek 故障时自动接管。两周试运行结束后，依据用户盲评、工具与 JSON 正确性、歧义追问、越权拒绝、延迟、失败率、实际 token 和人民币费用共同确认正式默认；若 Qwen 更合适，可以更换主次，不把当前选择永久锁定。

首次配置硅基流动时必须明确显示供应商、模型分层和最小发送内容，并记录当时的隐私政策日期。2026-07-29 版硅基流动隐私政策称交互数据归用户所有，平台只按指示处理且不作非授权使用、披露或存储；界面仍不能把动态供应商条款表述成永久零留存保证。私密记忆仍需额外允许，仅限本机资料仍禁止发送。实施和每次重要版本升级前重新核对模型 ID、功能、价格和隐私条款。

第一版对所有已配置云端模型供应商合并执行每个本地自然月 30 元人民币的默认费用硬上限，用户可以修改。累计估算费用达到 15 元和 24 元时分别提醒；预计单次请求费用超过 1 元时，发送前显示模型、用途、预计区间和剩余预算并等待用户确认。达到 30 元后停止发起新的云端 AI 请求，不自动充值，也不允许两周复盘或其他后台任务绕过；只有用户明确提高当月上限后才能恢复。确定性监督核心、按钮、表单、模板和本地记录继续正常运行。

费用硬上限覆盖 DeepSeek、Qwen 对照测试和以后新增的所有云端供应商，不能通过自动换模型重新获得另一份预算。Jarvis 保存每次请求的供应商、模型、用途、输入/输出/缓存 token、当时价格版本和计算费用，并与供应商账单或余额定期核对；发送前按照最大允许输出和剩余预算保守估算，价格变化或用量字段不完整时宁可要求确认或暂停，不能静默超额。费用记录不额外复制完整私人提示词。

第一版采用用户自带供应商凭据，不在安装包内置供所有安装共享的 DeepSeek、Qwen 或其他云端模型密钥，也不经过项目自建服务器代转模型请求。用户在供应商官方平台创建、充值、撤销并承担自己的 API 账号费用；Jarvis 只在用户明确配置后代表该账号调用。每个供应商使用独立凭据，不能把一个平台的密钥当作另一平台的故障备援。

供应商凭据使用 Windows 凭据管理器的当前用户、当前电脑持久化范围保存，不跨电脑漫游。只有 `Jarvis Core` 在实际调用时读取明文；`Jarvis Desktop` 可以提交新增或替换操作，但不能读回完整密钥，设置界面只显示供应商、连接状态和末四位。密钥不得写入 SQLite、普通配置文件、日志、崩溃报告、费用记录、数据导出、密码保护备份或百度网盘目录，也不得发送给 AI 模型本身。

更换电脑、从密码保护备份恢复或凭据丢失后，用户必须重新输入供应商凭据；备份密码不能解出 API Key。删除某个供应商配置时同时删除对应的本机凭据，并提示用户前往供应商后台撤销旧密钥；Jarvis 不能声称删除本机副本等同于供应商密钥已经失效。密钥无效、过期、欠费或被撤销时，AI 明确降级并提供重新配置入口，确定性监督核心继续运行。该保护沿用既有本机威胁边界，不承诺抵御已经登录同一 Windows 账户的恶意软件。

两个进程之间暂定使用仅限当前 Windows 登录会话的本地命名管道通信，不开放网络端口。`Jarvis Core` 是监督状态和 SQLite 写入的唯一权威；`Jarvis Desktop` 只能读取状态、接收事件和提交待核心验证的用户命令，不能直接修改数据库。界面重新连接时先取得完整状态快照，再继续接收变化。命名管道属于可替换的内部实现方案；未来可以在保持本机通信、核心独占写入、命令验证和重连恢复这些产品保证的前提下更换。

`Jarvis Desktop` 检测到与 `Jarvis Core` 的连接中断后，必须立即把桌面状态切换为明确的“监督已中断”，不得继续显示正在监督。Desktop 立即尝试重启核心一次；失败后分别在 10 秒和 30 秒再试，总计三次。三次均失败后停止自动循环，持续显示故障状态和手动重试入口。第一版不为此增加第三个常驻看门狗进程；若 Core 与 Desktop 同时退出，只能在用户重新启动 Jarvis 或下次 Windows 登录自启动时恢复。从最后一次确认核心正常到恢复观察之间的时间统一记为无法观察，不推测相关或偏离。核心恢复时，若承诺仍在进行，Jarvis 简单询问一次后继续监督；若承诺已经结束，则进入待回顾。恢复过程不能静默放弃或伪造提醒记录。

Windows 托盘图标由 `Jarvis Core` 持有，因此 `Jarvis Desktop` 隐藏、重启或崩溃时托盘仍保持可用并显示核心监督状态。托盘中的“隐藏桌宠”只关闭可见界面，监督继续；“重新打开桌宠”启动或唤醒 `Jarvis Desktop`；“完全退出”在明确提示监督将停止后，同时结束两个进程。界面关闭按钮默认不得等同于完全退出。

`Jarvis Desktop` 非预期退出时，`Jarvis Core` 自动重新启动界面并恢复当前状态；用户主动隐藏或关闭界面不算崩溃，不触发自动重启。若桌面进程在 5 分钟内连续崩溃 3 次，核心停止循环重启，继续监督，并在托盘明确显示“桌面界面故障”，提供手动重试和查看错误入口。恢复界面不得清除或重写崩溃期间由核心形成的监督记录。

第一版以用户当前目标电脑作为资源验收环境。`Jarvis Core` 与桌宠常驻、完整功能面板关闭时，两个进程在十分钟稳定空闲窗口内的合计内存工作集平均值不超过 320 MiB、采样峰值不超过 350 MiB，稳定空闲期间合计 CPU 平均占用低于 1%；打开对话、设置、复盘或知识等完整面板时，合计内存工作集目标不超过 800 MB。AI 请求、备份、启动、加载资源和状态动画允许短时超过稳态指标，但不能形成持续高占用，并应在操作结束后回落。以上数值是第一版性能验收基线，不是达到数值就强制终止进程的运行上限；稳定场景持续超出时按性能缺陷处理。2026-08-12，用户根据 T03 在目标机取得的十分钟同窗双进程证据（平均 297.749 MiB、峰值 309.168 MiB、CPU 平均 0.156%）确认从原先单一 300 MB 上限修订为当前的平均值与峰值双门槛，避免为了约 9 MiB 的短时超出重写低价值的托盘底层。

### 第一版消息渠道

第一版选择飞书企业自建应用承载手机端消息提醒和回应，企业微信保留为账号权限或接口实测失败时的备选。飞书只服务用户办公期间的监督互动，不建设电脑关机后仍常驻在线的云端 Jarvis；只有 Windows 端正在运行并能够执行监督逻辑时，才需要向手机发送消息。第一版优先支持自然语言回复和必要的快捷操作，具体权限、额度及手机通知表现使用目标账号实测确认。

飞书首次绑定时一次性确认企业自建应用、`bot` 身份和唯一的本人账号。只要绑定未撤销且目标、身份、权限与凭据未变化，Jarvis 按既定内容边界向该本人账号发送日常监督、复盘提醒和每日或周期总结时不逐条重复确认，也不为此建设复杂的逐消息确认逻辑。首次或重新绑定、增加或更换收件人、任何群聊发送、发送日常范围之外的敏感内容、扩展权限，以及新增、更换或删除飞书凭据仍需明确确认；Core 日常使用已配置凭据不算凭据变更。

第一版通知预览只提供一个全局两档设置。默认“隐私”档使用通用提示；用户可选“详细”档，让预览尽可能显示监督卡片允许的当前工作承诺、原定起止、连续偏离时长和活动类别四字段摘要。飞书或手机系统的隐藏预览设置优先，Jarvis 不绕过。两档都永不包含软件名称、网站域名、窗口或网页标题、文件名、截图、输入文字、聊天或文档正文、用户回复、复盘正文或个人记忆。第一版不增加按项目、时间段或逐消息的预览规则。

## 最终文档怎样进入产品

- 本台账保存访谈中的完整共识、未决问题和后置需求，是后续规格的来源，不直接作为单一 AI 提示词使用。
- 监督的时间、状态、分类、提醒和修改规则将在访谈结束后整理成独立、可测试的监督规格，由程序执行。
- AI 行为、对话方式、权限边界、承诺回顾和复盘方法将整理成 AI 行为规格，并据此形成系统提示词和可调用操作的约束。
- 当前工作承诺、监督状态及必要的个人记忆将在运行时按需提供给 AI，不把全部历史和私人资料无差别塞入上下文。
- 领域术语表和 ADR 用于确保后续由人或开发 Agent 实现时仍沿用相同概念和边界。

## 第二版已确认检查点（2026-08-26）

### 最小充分设计

第二版不把第一版后台设置原样搬进新界面，也不建设通用手机产品、云端账号体系或复杂自动进化系统。主干收敛为：一个对话中枢、记录/提醒/监督三种用户意图、简化模板、电脑轻监督、用户当前华为手机的应用阻断，以及记录驱动的每日和每周复盘。底层继续沿用工作承诺、确定性监督核心和版本化事实；界面可以把工作承诺简写为“监督”。

### 对话中枢与操作确认

- 对话中枢是桌面端唯一主要交互窗口；自然语言和嵌入式结构化卡片共同承载记录、提醒、监督、回应和复盘。
- 一个窗口不等于只有纯文本。设置、历史和权限是由对话中枢进入的次级页面，不与聊天竞争主入口。
- 记录等低风险操作可以直接完成并允许撤销；启动监督、修改工作承诺、改变应用阻断或加强监督等高影响操作必须展示简洁确认卡。
- AI 只生成候选操作；确定性核心校验意图、时间、权限、模板和规则后才写入正式数据。歧义时追问，不能用猜测替代确认。

### 三种用户意图

- **记录**：没有必需执行时间的想法、灵感或普通笔记，保存原始文字或确认后的语音转写，不自动变成提醒或工作承诺。
- **提醒**：具有指定时间和处理结果，到期提醒但不监测活动、不屏蔽应用。取消或日终仍未完成时必须保存用户原始原因；单纯未回应只记为未回应。
- **监督**：界面对正式工作承诺的简写。只有用户提前主动布置、查看确认卡并确认后，才会在生效期内监测电脑和启用手机应用阻断。
- 不单独建设重型待办系统；具有完成状态的待办按提醒事项处理。

### 简化模板

- 模板只保存常用目标、默认持续时间、电脑相关应用或网站、被动型或交互型监督、手机阻断应用和提醒阈值。
- Jarvis 可以从“交易复盘”等自然语言匹配并填充模板，但仍展示确认卡。
- 临时修改不会反向污染模板；只有用户明确表达“以后都这样”时才更新。
- 第二版不在模板中保存语气、复杂执行步骤、复盘问卷或自动学习规则。

### 电脑监督

- 监督模式只保留被动型和交互型，不建设混合型或自动阶段切换；默认被动型。
- 被动型在相关应用或网站保持前台时，不因键鼠空闲判断偏离。交互型可以在持续空闲时询问，但空闲仍不是成果未完成的证明。
- 继续使用应用、网站域名和活跃/空闲等非内容信号；不因第二版加入聊天和活动账本而把输入、正文或截图变成监督证据。
- 交易复盘模板默认把 TradingView 与 Notion 设为相关活动，但第二版不接入、读取或修改二者的内容或 API。

### 私人手机监督端

- 第二版只面向用户自己的 HUAWEI Mate 70 Pro+（PLA-AL10，HarmonyOS 4.3.0），采用私人手动安装，不承诺其他机型或公开市场分发。
- 专用手机端替代 V1 飞书监督入口，只提供最近消息、提醒回应、快速文字/主动语音记录、应用阻断和临时开放；不建设完整设置、历史管理、独立复盘或离线 AI。
- 手机监测和阻断只在已确认工作承诺生效期间运行，并持续显示监督状态。产品目标是在承诺开始后尽力覆盖阻断抖音、B站、小红书和手机微信；电脑微信不受影响。不锁整台手机，也不以累计五分钟作为手机阻断前提。
- 官方资料只支持私人签名 APK 侧载，不支持普通非 root/非企业管理应用拥有系统级暂停其他包的权限；当前最小候选是前台包识别加全屏覆盖层的尽力型阻断，必须通过目标真机量化 spike，不能声称不可绕过。HarmonyOS 5 / NEXT 默认不兼容。
- 用户填写原始原因后可以临时开放被阻断应用五分钟；到期自动恢复阻断，开放事件进入承诺回顾和周期复盘。
- 已确认策略同步到手机后，即使电脑离线，手机也只按该策略执行到原定结束时间；离线时不得自行延长或加强。恢复连接后同步事件。
- 电脑与手机优先通过同一局域网配对，不建设项目云端后端。手机端能力、权限或后台存活失败时，电脑监督照常开始并明确显示监督降级；不能伪装成手机阻断仍有效，也不能自动归咎于用户。
- 上述应用识别、阻断、后台存活和私人安装能力均以真机技术原型为交付门槛；公开资料不能证明的部分在验证前保持“需验证”。

### 记录、活动事实与复盘

- 所有想法进入同一个记录库，始终保留原始表达；AI 可以添加可编辑的标题、标签、关联和完善版本，但不建设第二套“晋升长期记忆”的流程。
- 经一次明确授权后，本机可以形成全天粗粒度活动事实账本，只记录应用、网站域名、活跃/空闲和时间。它用于复盘时提出“可能做过什么”，不能自动宣判成果完成。
- 原始活动事实默认保留 30 天，之后只保留每日汇总；记录、提醒、工作承诺、原始原因、想法和确认后的复盘长期保存，直到用户删除。原始语音不长期保存。
- 每日复盘默认用 5—10 分钟对话整理工作承诺、提醒、活动事实、记录和主观感受；每周复盘用 20—30 分钟识别反复问题和下周改进。
- Jarvis 每周最多建议一项监督规则调整，展示证据并由用户确认后生效，且可以撤销；不建设独立实验管理系统，也不能自动加强监督。

### 表达与普通提醒

- 第二版只保留一个全局默认语气；用户可以用自然语言临时要求本次更严肃、俏皮或撒娇。语气不写入模板，也不改变事实和监督强度。
- 普通提醒在到期时通过桌面和手机提醒；30 分钟仍未处理时再提醒一次，随后只保留持续可见但不闪烁的待处理状态，日终复盘解决，不无限轰炸，也不触发应用阻断。

### 交付顺序

- **V2-A**：对话中枢与卡片、记录/提醒/监督、简化模板、电脑监督、华为手机阻断与临时开放、离线策略执行、承诺回顾和文字想法记录。
- **V2-B**：主动语音、全天活动事实账本、每日/每周复盘、想法关联与 AI 完善、下一周期一项监督调整建议。
- V2-A 以“创建交易复盘监督—同步并阻断手机—电脑执行—临时开放—结束回顾”的完整场景验收；V2-A 未通过前不进入 V2-B。

## 第一版已确认

### 产品核心定位

Jarvis 第一版首先证明“个人执行监督伙伴”的价值，而不是优先成为普通桌宠、通用 AI 助手或完整知识管理工具。

### 第一版核心闭环

第一版围绕以下闭环继续细化：设定工作承诺、观察履约情况、发现偏离、发出提醒、记录是否恢复工作、晚间引导复盘。

### 监督依据

用户主动设定的工作承诺，是第一版判断是否履约的唯一正式依据。Jarvis 可以在以后根据习惯提出建议，但不能未经确认就改变监督标准。

### 预定承诺的生效方式

预定工作承诺在计划开始时间自动生效，不依赖用户主动点击“开始”。用户可以推迟、取消或声明例外，但这些操作及原因必须被明确记录，不能静默跳过。

### 第一版的自动监督边界

第一版只自动监督需要使用受监测电脑完成的工作承诺。线下任务可以被计划、提醒和手动确认，但 Jarvis 不根据电脑状态自动判定线下任务是否履约。

电脑关机、休眠、离线或 Jarvis 未运行时，不要求手机端继续发送监督提醒。第一版不为该场景专门建设独立于电脑运行的远程看门能力；手机提醒只需在电脑端能够运行监督逻辑时发出。

电脑恢复运行后，缺少活动证据的期间标记为无法观察，不自动算作相关活动或偏离，也不补发已经过时的手机提醒。若工作承诺仍在进行，Jarvis 简单询问后继续监督；若承诺已经结束，则进入待回顾队列，由用户用自然语言补充情况。

### 第一版的电脑活动监测边界

第一版默认只使用以下活动证据：键鼠是否处于活跃状态、当前使用的软件、浏览器当前网站的域名。窗口标题、文件名和网页标题需要单独授权。第一版不记录具体按键、点击位置、剪贴板、聊天正文、截图、录屏或文档正文。

用户明确希望未来接入 AI 后，Jarvis 能够进一步理解点击对象、正在使用的软件、输入的文字、聊天和屏幕画面。这些成长上下文主要服务于长期陪伴、自我成长、复盘和知识整理，不是提高监督精细度的前置条件。该长期方向不受第一版边界排除，但必须在实现前继续明确授权方式、禁用范围、即时处理与长期保存的区别。

### 监督与成长上下文的长期边界

监督判定只能依据用户明确设定的工作承诺和有限活动证据。聊天、输入文字、截图等成长上下文可以帮助 Jarvis 陪伴用户、辅助复盘和提出建议，但不能独立成为违约证据，也不能独立触发监督升级。

### 软件和网站的活动分类

当前软件或网站相对于工作承诺分为相关、分心和未确定三类。未确定活动可以触发 Jarvis 询问用户并在确认后形成规则，但不能在未经确认时直接判定用户违约。未来可以根据历史提出分类建议，最终分类仍由用户确认。

未确定活动连续约 5 分钟后，Jarvis 在本机询问其与当前工作承诺的关系。用户可以将其标记为仅本次相关、对当前承诺模板持续相关或属于分心。确认相关时撤销此前的偏离计时；确认分心时从最初进入该活动开始计算。若一直没有回应，达到 20 分钟时发送措辞中立的手机提醒，不直接宣称用户违约。后来补充分类时，应重新修正对应活动记录。

活动分类具有全局默认、承诺模板和单次承诺三层作用范围。发生冲突时按单次承诺、承诺模板、全局默认的顺序优先。Jarvis 在保存新分类前必须明确展示其作用范围，不能擅自把单次例外升级为永久规则。

### 分级提醒

偏离工作承诺时先在本机进行轻量提醒，持续偏离达到严重阈值或长期没有回应时再升级到手机提醒。对于明确使用分心软件或网站，当前默认参考值为连续约 5 分钟后本机提醒、达到 20 分钟后手机提醒；电脑空闲采用单独的休息确认节奏。阈值以后可以全局调整，也可以为特殊工作承诺单独设置。

工作承诺到点自动生效时只在电脑桌宠上显示开始提示，不发送飞书。连续偏离约 5 分钟的第一次轻提醒同样只在本机出现；只有连续偏离达到 20 分钟时，才升级为飞书消息。第一版不把每次开始工作或短暂分心同步到手机，避免高频消息削弱严重提醒的注意力价值。

约 5 分钟的本机轻提醒由桌面形象播放一个短动作并显示简短文字气泡。同一次连续偏离首次触发该轻提醒时，默认播放一次约 1 秒的低音量提示音，之后持续偏离期间不再重复播放；偏离结束后出现新的连续偏离，才重新获得一次提示音。提醒不调用 Windows 系统通知，不抢夺键盘焦点，不弹出模态窗口，也不创建覆盖当前工作区的额外强制置顶界面；气泡和动作必须避开当前输入区域。工作监督不自动朗读提醒内容，用户可以全局关闭提示音。

稳定处于相关活动时不触发轻提醒，也不播放提示音；“工作期间播放提示音”只指同一次连续偏离达到首次本机轻提醒条件后的反馈。全局静音、安静模式、全屏、会议和公开场合模式下自动静音，但静音本身不改变监督状态或偏离计时，也不会在退出静音后补播已经错过的声音。

桌面形象因全屏自动收起后，如果当前全屏软件已经被明确分类为分心并持续约 5 分钟，Jarvis 从屏幕边缘短暂显示无声提醒气泡，不抢焦点，也不展开完整角色。安静模式、会议、演示和公开场合模式下不显示该气泡；偏离计时继续，达到 20 分钟时仍可按既定规则升级到飞书。相关或未确定的全屏活动不因全屏本身触发这一例外。

本机轻提醒气泡默认显示约 10 秒后自动收起，但收起只结束气泡展示，不代表偏离已经解决，也不停止偏离计时。桌面形象随后保留一个克制且不闪烁的提醒状态标记，直到电脑端观察到稳定的相关活动，或用户通过休息、误判、调整承诺等明确操作处理当前状态。关闭气泡不能顺带清除该标记。

点击提醒状态标记时，桌面形象旁展开一个不抢键盘焦点的小面板，不打开完整对话窗口。面板显示当前工作承诺、连续偏离时长，以及“马上回去”“当前活动相关”“限时休息”“调整承诺”四个入口。“马上回去”只记录意图并等待活动证据确认真实恢复；“当前活动相关”继续要求选择本次、承诺模板或全局作用范围；“限时休息”必须给出结束时间；“调整承诺”沿用承诺修订和原因记录规则。

关闭或忽略提醒只关闭当前界面，不停止偏离计时，也不阻止后续升级。只有稳定返回相关活动、确认未确定活动实际相关，或显式暂停、推迟、取消、声明误判或特殊例外，才能改变监督状态；点击“返回工作”后仍需观察到实际相关活动才重置计时。

同一次连续偏离在达到 20 分钟时发送第一次手机提醒；仍未回应或恢复时，此后每隔 20 分钟再提醒，最多发送 3 条。实际恢复工作、显式修改承诺或监督时段结束时，立即取消尚未发送的后续提醒。以后可以为特殊工作承诺选择更严格或宽松的提醒强度。

手机提醒必须允许用户采取最低限度的回应操作，包括表示准备返回工作、确认休息及剩余时长、推迟或取消承诺、声明误判和补充自然语言说明。手机端表示返回工作不会直接重置计时，仍需电脑端观察到稳定的相关活动。第一版通过飞书交互卡片和平台内自然语言回复实现，不额外建设手机网页。

第一版的 20 分钟飞书提醒使用交互卡片并同时接受自然语言回复。卡片提供“马上回去”“确认休息”“调整承诺”“这是误判”等少量高频入口；需要说明原因、感受或复杂情况时，用户可以直接使用口语化文字回复。Jarvis 从回复中提取相应操作和结构化类别，但必须保留原始表达；存在歧义或涉及推迟、取消等重要变更时先向用户确认，不能只凭 AI 猜测直接修改承诺。

手机锁屏和系统通知横幅遵循“第一版消息渠道”已经确认的全局两档预览规则：默认“隐私”档只使用通用提示，可选“详细”档尽可能显示卡片允许的四字段摘要，平台隐藏预览设置始终优先。无论选择哪一档，都不得展示软件名称、网站域名、窗口或网页标题、文件名、截图、输入文字、聊天或文档正文、用户回复、复盘正文或个人记忆；两档都需要在目标手机上实测。

进入飞书后，监督卡片仍遵循最小披露原则，只显示当前工作承诺、原定开始与结束时间、连续偏离时长，以及分心、空闲或未确定的活动类别。第一版不把具体软件名称、网站域名、窗口标题、文件名、截图、输入文字、聊天正文或文档内容发送到飞书；这些信息即使在本机可用，也不能为了丰富提醒而自动附加。

每张飞书监督卡片只对应发送时的那一次连续偏离和当时有效的工作承诺版本。用户已经稳定恢复相关活动、承诺结束或取消、监督规则经过修订，或者该次偏离以其他方式结束后，旧卡片立即失效。用户之后点击旧卡片时，只提示“当前状态已变化”并展示当前有效状态，不得再次执行休息、调整、误判或返回工作等操作，也不得改写已经形成的历史记录。

同一次连续偏离需要再次升级提醒时，每隔 20 分钟发送一张新的飞书卡片，并在新卡片生效时立即使上一张卡片失效。新的卡片使用发送当下的偏离时长和有效承诺版本；历史卡片保留用于查看，但不能操作。该规则不增加提醒总量，同一次连续偏离仍然最多发送 3 张飞书卡片。

用户点击卡片按钮或自然语言回复被明确处理后，Jarvis 直接将当前卡片更新为不可重复操作的结果状态，例如“已记录休息至 15:20”或“已记录返回意图，等待电脑端确认”，不再额外发送一条确认消息。只有回复存在歧义、缺少休息结束时间，或涉及尚未确认的推迟、取消和承诺修订时，才发送新的追问；追问完成后同样回写原卡片的最终结果。

不同回应采用不同记录强度：实际恢复工作由系统自动记录时间，不要求解释；确认相关活动或误判时记录分类范围和纠正结果，说明可选；临时休息必须指定结束时间，原因可选；推迟、取消或特殊例外必须留下自然语言原因；没有回应时如实记录未回应。Jarvis 可以从自然语言中提取统计类别，但必须保留原始表达并允许用户纠正。

### 休息与电脑空闲

工作承诺可以预设计划休息，也可以由用户主动发起有明确结束时间的临时休息；休息期间暂停监督，到期自动恢复。交互型工作中若未预先声明休息，电脑连续空闲 10 分钟后 Jarvis 询问是否在休息。确认后把休息起点追溯到本次连续空闲开始时，当前默认总休息时长为 15 分钟，并在到期时提醒返回工作。未回应或否认休息时，空闲继续计入偏离计时，达到 20 分钟后升级到手机。上述时长均可配置。

### 交互型与被动型监督

每个电脑型工作承诺具有监督模式。交互型适用于写作、编程和整理资料等需要持续操作的工作，长时间没有键鼠输入可以进入偏离计时；被动型适用于阅读、课程和线上会议，只要相关软件或网站仍在前台，就不因没有输入而判定偏离。默认使用交互型，被动型需要用户明确选择；切换到无关内容或锁屏仍可进入偏离计时。

### 偏离计时的连续性与重置

在分心活动、空闲及其他不能确认相关性的状态之间切换，不会重置偏离计时。短暂切回相关软件也不会立即清零；只有相关活动持续经过短暂稳定期后才重置，当前默认参考值为 2 分钟。主动暂停、推迟或声明例外可以结束本次计时，但必须留下记录。若用户确认某项未确定活动实际与工作相关，应撤销对应误判并记住新的活动分类。

### 工作承诺的创建确认

无论通过表单还是自然语言创建，工作承诺在正式成立前都必须以承诺卡片展示目标、开始与结束时间、监督模式、活动分类规则和提醒阈值，并由用户确认。确认后的预定承诺到点自动生效，无需再次点击开始；会改变监督结果的修改需要留下版本记录。

承诺卡片最少需要开始与结束时间（或开始时间与持续时长）、至少一个投入目标或成果目标，以及至少一个相关软件或网站。监督模式默认交互型，提醒使用已确认的默认配置；其他活动分类和休息规则可以继承全局设置或承诺模板。创建入口支持复用模板、简短表单和自然语言，Jarvis 补齐默认值后仍需展示承诺卡片供用户确认。

工作承诺的目标可以是投入型、成果型或两者结合，并且至少填写一种。投入型目标约定投入时间或工作过程，成果型目标约定要产生的结果；承诺回顾时分别询问时间投入和成果完成情况，不能用坐满监督时段代替成果完成。

预定工作承诺到点后立即自动生效并显示开始提示。默认前 5 分钟为准备缓冲；缓冲期间允许用户切换环境和打开相关工具，不进行首次本机偏离提醒。达到 20 分钟时的手机升级仍从计划开始时间计算，不因准备缓冲而顺延。

工作承诺生效后仍允许修订目标、结束时间、活动分类和提醒规则，但修订从确认时刻向后生效，并保留旧版本、修改原因、既有提醒和偏离记录。明确的系统误判可以在保留纠正说明的前提下重新计算对应记录；不得通过倒改开始时间等方式静默隐藏历史。

### 承诺模板与重复承诺

承诺模板保存目标、常用时长、监督模式、活动分类规则和提醒阈值等可复用设置，但不包含必须执行的具体日期。重复承诺按照日期规则生成一系列彼此独立的工作承诺。修改重复承诺产生的工作承诺时，需要明确区分只修改本次、修改本次及以后或修改整个重复安排。

### 第一版的重复日期规则

第一版支持每天重复、每周选择星期几重复、设置重复的起止日期，以及在若干不连续日期批量创建相同工作承诺。用户可以跳过或单独调整其中某一天。

### 监督时段冲突

第一版不允许两个电脑型工作承诺的自动监督时段重叠。创建或修改产生冲突时，用户必须调整时间或明确选择其中一个。临时切换工作时，需要先结束、暂停、推迟或取消当前承诺，并记录切换原因。

### 监督结束与承诺回顾

计划结束时间只代表停止本次监督，不自动代表目标已经完成。监督结束后，Jarvis 主动邀请用户进行承诺回顾；用户以自然语言说明完成状况、过程和感受，Jarvis 保存原始表达，并可整理出已完成、部分完成、未完成等结构化状态及复盘要点。用户也可以提前完成并进入回顾；未回应时保持等待回顾，不能自动记为完成。

第一版的承诺回顾同时支持自然语言文字输入和由用户主动触发的语音输入，不持续监听。语音转写结果必须允许用户确认、补充和修改；默认长期保存确认后的文字，不长期保存原始录音。

### 延后的承诺回顾

监督结束时，用户可以选择立即回顾、稍后提醒或明确跳过。选择稍后或没有回应时，工作承诺进入待回顾队列，不连续重复打扰，并在晚间总结时集中带出。明确跳过时记录“本次未回顾”，不自动推断完成情况。

### 监督记录的保存期限

软件、网站、空闲、休息等详细监督时间线默认保存 90 天，期限可以调整。到期后删除详细轨迹，只保留每日活动汇总。工作承诺、承诺修订、完成结果和承诺回顾长期保留。用户可以按日期范围查看、导出和永久删除；监督记录不包含具体按键、聊天正文、截图等成长上下文。

### 每日复盘的内容

每日复盘采用对话形式并且一次只问一个问题。Jarvis 先客观概括当天的工作承诺、完成结果、偏离、休息和提醒情况，再逐项补完待回顾承诺；随后讨论做得好的地方及原因、不理想之处及其可能属于计划、外部打断、身体、情绪或执行等哪类问题，最后共同确定次日最多一至三项具体调整。用户可以用文字或主动语音自由补充；系统保留原始表达并整理结构化复盘记录，供后续周期总结使用。

每日复盘默认在本地时间每天 23:00 提醒，因为用户通常在 22:00–23:00 进行交易；该时间可以在设置中修改。到点时若有交易或其他工作承诺仍在进行，则自动顺延到该承诺结束后；当天提前主动完成复盘时不再重复提醒。即使当天没有工作承诺，也允许照常复盘生活、状态和临时事项。

每日复盘提醒不依赖某项工作承诺仍在监督中，但只在 Windows 端正在运行时发出。到首选时间时电脑关闭、离线或 Jarvis 未运行，不通过手机补发复盘邀请；下次 Jarvis 启动并与用户互动时，将该次复盘列为待补。电脑离线本身不被视为偏离，也不触发监督类消息。

首次每日复盘提醒未回应时，默认 30 分钟后只追问一次，并提供立即复盘、延后 30/60 分钟或跳过选项。当晚仍未完成时记录为每日复盘待补，不自动生成总结；第二天首次与 Jarvis 互动时只询问一次是否简短补做，再次跳过或不回应后记录昨日未复盘并停止追问。提醒间隔可调整。

### 桌面形象的存在方式

Jarvis 默认以小型透明背景角色常驻桌面并置顶，可以拖动和吸附屏幕边缘，不遮挡主要工作区域。平时保持安静，点击后展开对话或操作面板；支持临时隐藏、安静模式和完全退出。检测到全屏、演示或用户指定的软件时自动收起，但后台监督继续运行。托盘图标始终提供找回角色和退出程序的入口。

### 伙伴型教练与亲密陪伴人格

Jarvis 的稳定内核是伙伴型教练：日常像熟悉用户的朋友，安排事务时清楚简洁，监督时坚定且基于工作承诺，复盘时通过追问帮助理解原因，不羞辱、不道德评判，也不制造愧疚。

在此基础上增加可调节的赛博女友式亲密陪伴人格，通过亲密称呼、恋爱式语气、动作和日常关心增强陪伴感，但不能改变监督规则、数据权限或用户控制权，也不能以生气、吃醋、冷落或感情承诺操纵用户。第一版不制作亲密度数值、关系阶段、约会、纪念日或其他复杂恋爱养成机制。

亲密表达按照场景自动调节：工作监督时保持较轻的亲密感并简短明确，不能用撒娇冲淡规则；承诺回顾和每日复盘时更加温柔支持；普通闲聊和休息时可以充分使用亲密称呼、关心和互动。用户可以随时切换到专业模式，并配置不喜欢的称呼、语气和互动边界；切换只影响表达，不影响记忆和监督。

第一版只使用一位身份稳定的女性 Jarvis 角色。可以更换服装、配色、发型或主题，但仍是同一个 Jarvis，外观变化不改变人格、记忆或监督规则。多角色切换和多桌宠并存后置。

第一版先使用 AI 生成的透明背景 2D 临时角色素材，只制作待机、工作、提醒、开心和关心五组基础状态。眨眼、呼吸、轻微位移和靠近等表现由 WPF 简单变换完成；休息、说话和睡眠等场景复用基础状态并叠加小标记，不单独扩展完整资产组。第一版不引入 Live2D、Spine 或 3D；角色形象经过实际使用验证后，再替换为正式素材而不改变监督和 AI 内核。

没有工作承诺时，桌面形象可以偶尔沿屏幕边缘小范围走动、坐下或换姿势；工作监督期间保持固定位置并使用安静的工作动画。提醒时可以短暂靠近当前窗口边缘，但不能遮挡输入区域。默认不自动跨显示器；自动移动可以关闭，并提供回到默认位置的操作。

第一版保留服务用户的基础互动：拖动并记住位置，单击开始对话或作出轻触反应，悬停显示当前承诺或状态，右键菜单提供创建承诺、开始休息、专业模式、隐藏和退出等快捷操作，并支持调整大小与鼠标穿透。状态变化通过动作、表情和短气泡表达。

无负担陪伴是长期原则。Jarvis 不设置饥饿、健康、金币、投喂、商店、小游戏数值、亲密度或其他要求用户照顾和维护的机制；忽略互动不会带来数值惩罚、关系惩罚或情感施压。后续新增互动也必须以服务用户为目的。

Jarvis 必须能够主动发起闲聊和关心，而不只是被动等待用户点击。工作承诺进行时仍保持安静，只进行与工作相关的必要互动；用户忽略主动闲聊时不追问、不失落，也不产生任何惩罚。

主动闲聊频率采用自适应方式：初始每天在非工作时段主动发起一至两次；用户经常回应并愿意继续时可以逐渐增加，连续忽略时自动降低但不表现失落。用户可以直接要求当天多陪伴或安静；睡眠、全屏和工作承诺期间保持静默。

Jarvis 支持语音输出，但所有内容始终可以通过文字气泡查看。默认声音是成年、温柔、自然的普通话女声，音色略偏中低、语速稍慢，不使用幼态娃娃音或夸张动漫腔；工作相关表达清晰直接，普通闲聊、承诺回顾和每日复盘时更加柔和。工作监督默认只使用动作、文字和短提示音，不突然朗读私人内容。用户主动发起语音对话时，可以在本轮自动使用语音回应。产品提供全局静音、仅耳机播放和临时静音，不在公共场景自动念出工作目标、聊天内容或复盘内容。

第一版只交付一套完整的 AI 临时角色素材；最低限度的主题切换只改变强调色、名牌或简单覆盖层，不再复制整套状态资产。第一版不做衣服、发型和饰品的自由组合，也不做商城、货币、解锁任务或照顾奖励。正式角色和其他完整外观包在核心监督闭环验证后再制作。

第一版默认美术方向为具有成年感的半 Q 版二次元女性角色：银灰色中长发，以深蓝黑为主色，使用青蓝与淡紫的微光点缀，穿简洁的未来感办公外套。整体气质温柔、聪明，适合长时间放在工作桌面；角色比例需要在小尺寸下仍能看清表情和动作，避免幼态儿童感、夸张暴露设计和厚重机甲。外观包机制不能锁死该风格，后续允许增加明显不同的整体外观。

后续增加公开场合模式：在他人在场、办公或屏幕共享时切换为克制的职业外观或抽象科技形象，并隐藏亲密称呼、亲密气泡、主动闲聊、语音和私人信息。内部仍是同一个 Jarvis，记忆、监督和状态不中断；离开公开场景后可恢复日常外形与亲密表达。

首次设置时明确询问并推荐开启 Windows 登录自启动，不得静默启用。登录后先启动后台监督，再显示桌面形象；设置和托盘中可以随时关闭。关闭自启动但存在未来工作承诺时，需要提示程序未运行将无法监督。隐藏桌面形象不影响后台监督，完全退出则必须明确告知监督停止。

### 个人成长档案优先

自我成长阶段先建立个人成长档案，优先记录用户的长期目标、当前项目、重视的事情、明确偏好和边界、监督与复盘中反复出现的行为模式，以及哪些提醒、鼓励和工作方法有效。外部知识图谱在个人成长档案稳定后再单独设计。

个人成长档案严格区分已确认信息、观察模式和待确认推测。只有用户明确表达或亲自确认的信息可以稳定影响 Jarvis 的长期行为；观察模式需要多次记录、证据和可信程度，只用于温和提问；待确认推测不能成为长期事实或自动决策依据。用户可以查看、修改、否认或删除任何内容，不因单次事件形成懒惰、自制力差等永久标签。

资料学习采用显式授权。用户计划授权 `D:\Desktop\codex` 整个工作目录作为资料源；原始文件保持只读，Jarvis 不扫描其他未授权位置。授权不意味着立即批量读取并形成完整用户画像，而是在后续聊天、复盘和具体项目中按需读取相关内容，逐步提出可确认的记忆、模式或知识。当前需求访谈阶段不执行全量导入。

即使目录已经授权，也默认排除 `.env`、密钥、令牌、密码和凭据、`.git` 内部数据、依赖目录、构建产物、缓存、临时文件、可执行文件及其他无须理解的二进制文件。明确标记为私密或禁止学习的目录同样排除；只有用户针对具体任务明确指定时才临时读取被排除文件，并且不自动进入个人成长档案。

授权目录包含多个项目和大量与认识用户无关的内容。Jarvis 只应提取有助于理解用户目标、选择、反思、偏好、行为模式和成长过程的资料，不能因为文件可读就把所有项目内容都写入个人成长档案。

值得记住的信息采用低打扰确认方式：用户明确说出的偏好或边界可以在轻量提示“已记住”并允许立即撤销后记为已确认信息；从多次行为中发现的观察模式集中在每日或两周复盘中确认；原因和性格方面的待确认推测只能在相关对话中询问。产品提供“Jarvis 记得的我”记忆中心，用于查看、搜索、修改、合并、否认和删除记忆；每条记忆显示来源与形成时间。

个人记忆具有时间和适用场景。新信息成为当前有效内容，旧信息标记为已替代并默认不再影响当前行为，但可以用于理解变化过程；疑似场景差异时先询问适用范围，而不是直接覆盖。临时情绪和短期状态具有有效期限，不自动变成永久性格。用户可以删除单条旧记录或完整变化历史。

Jarvis 的进化是个人成长档案逐渐准确、沟通方式逐渐适配，以及通过用户批准的限时行为实验验证更有效的服务方式。行为实验需要用户确认、明确期限、记录效果并可随时撤销。Jarvis 可以建议修改模板和监督参数，但不能自行修改工作承诺、核心监督规则、系统提示词、程序或权限边界；正式变化需要版本记录。

### 周期复盘的内容

周期复盘展示本周期计划与实际完成情况，分别呈现投入目标和成果目标；分析相关活动、偏离、休息、推迟和未回应的趋势；从每日复盘中整理有证据支持的有效做法和反复问题，并区分计划、外部打断、身体情绪和执行习惯；与上一周期比较真实变化；展示新观察模式和待确认推测供用户纠正；回顾行为实验效果；最后共同选择下一周期最多一至三个改进重点或新实验。每个判断都应能追溯到具体记录，不使用人格分数、自律值或制造焦虑的排行榜。

周期复盘默认每 14 天进行一次，初次设置时由用户选择固定复盘日和时间。周期可以改为 7 天、28 天或自定义天数；修改只影响未来安排，不重写过去的周期边界。到点未完成时进入周期复盘待补，之后择时完成，不自动跳过或生成总结。

### 个人知识图谱的定位

个人知识图谱优先用于回答用户过去学过什么、连接新内容与已有主题、项目和问题、发现久未接触且值得复习的内容、生成复习问题，并让每个结论追溯到来源文件、对话或记录。可视化关系图只是辅助浏览方式。个人成长档案记录关于用户的内容，个人知识图谱记录用户接触、理解和思考的主题；两者可以关联但不能混为一份画像。

知识图谱严格区分资料观点、用户观点和 AI 整理。资料观点必须标明来源；用户观点保留表达时间和上下文；AI 建立的联系、总结和推测必须清楚标记，不能冒充资料内容或用户观点。相互矛盾的资料可以同时保留并展示分歧；用户观点发生变化时当前观点优先，旧观点可保留为思考变化历史。

知识图谱不维护已接触、能够解释、已经应用、精通等复杂掌握等级。资料被读取不代表用户已经学会；系统只保留来源，并允许用户或 Jarvis 添加简单的“值得复习”标记。回答用户是否接触过某主题时，根据聊天、笔记和项目证据自然说明依据，不依赖等级标签。

知识复习由周期重心驱动。每次周期复盘确定下一周期的一至三个重心后，Jarvis 从知识图谱中选择与这些重心直接相关的关键知识，作为本周期值得复习的内容。重心变化后重新选择，不把旧标记无限累积成永久待办清单。复习采用低频对话方式，可以在相关话题中自然提醒，也可以在周期内推荐少量主题；不使用分数、连续打卡、题海或强制间隔重复。

每个周期的关键知识清单总计三至七条。Jarvis 需要说明每条内容对应哪个周期重心、为什么值得复习，并链接原始来源；用户可以确认、删除、替换或手动添加。上一周期的普通复习标记自动退出当前清单但保留历史；特别重要的内容可以长期置顶。周期中出现新的相关知识时可以建议加入，但不能无限扩张清单。

每日复盘结束时，Jarvis 最多提出三条知识更新候选，只包括当天新理解或改变看法的概念、项目实践中形成的重要结论、方法或教训，以及新出现的关键问题和它与已有知识的联系。普通软件使用、重复执行的工作和琐碎待办只留在监督记录中。候选显示来源和建议关系，由用户接受、修改或忽略；没有高价值内容的日子可以不生成。

### 成长上下文的启用边界

已授权的 Codex 文件和聊天资料可以按需直接读取，不需要监听键盘。其他软件中的实时成长上下文默认不开启，只能由用户按应用或按一次会话显式开启上下文模式；开启期间桌面形象持续显示状态并提供一键暂停。密码、支付、身份认证、隐私窗口和黑名单应用始终禁止采集。理解内容时优先使用软件接口、文档内容和窗口结构，只有不足时才临时使用截图。成长上下文只服务陪伴、自我成长和知识整理，不能用于监督判定。

上下文模式取得的原始截图、文字片段和点击信息只进入本机临时缓存，在会话结束时可以删除，最长保留 48 小时。AI 可以据此提出记忆或知识候选，但只有用户确认的提炼结果才长期保存。用户可以主动保留指定原文及其来源、时间和适用范围。授权文件继续以原文件为来源，不额外复制永久快照；删除原始内容后，系统仍需标明哪些提炼结果曾来自该会话并允许一并删除。不建立长期键盘日志、连续截图档案或可回放屏幕历史。

个人记忆具有普通、私密和仅在询问时使用三种可见级别。普通记忆可以在相关私人对话中自然引用；私密记忆只能在用户已经打开对话面板后引用，不能出现在桌面气泡、手机通知预览或自动语音；仅在询问时使用的记忆只有用户主动问到时才能读取和引用。健康、财务、关系、情绪和私人聊天默认建议标为私密；公开场合模式一律不展示。用户可以随时修改级别。

移除授权资料源时，需要让用户选择保留已经确认的记忆，或连同由该来源产生的记忆和知识一起删除；未确认候选默认随来源授权一同移除。保留的内容应标记原始来源当前不可用。

授权资料和成长上下文可以使用云端 AI 处理，但默认只发送完成当前问题所需的少量相关片段，不上传整个文件夹或完整历史。产品必须显示正在使用本地还是云端模型及其服务商；每个资料源可以单独选择允许云端或仅限本机，私密和仅在询问时使用的记忆默认需要额外允许。系统保留可查看的云端请求记录；仅限本机模式下能力不足时必须说明功能不可用，不能静默改用云端。
