# T15–T20 人工验收手册

本文是 T15–T20 的用户验收入口。开发交付边界、架构说明和自动化场景映射见
[`t15-t20-worktime-review-ai.md`](t15-t20-worktime-review-ai.md)。

## 验收原则

- 推荐顺序是 **T19 → T20 → T15 → T16 → T17 → T18**，不是按票号机械执行。
  先配置真实 AI，再用自然语言创建一条承诺，后面的手机提醒、结束回顾和复盘可以复用同一条数据。
- 人工验收只检查真实供应商、真实飞书和 Desktop 可见行为。并发、重启、费用原子性、重复事件、
  精确 20/30 分钟阈值等耗时或故障分支由自动化场景覆盖，不要求用户重复制造故障。
- 所有按钮结果都会显示在窗口底部固定的状态栏。正式承诺最终都在窗口最下方的
  **“Core 正式状态”** 表格中查看。
- 截图不得包含完整 API Key。AI 状态只应显示密钥末四位。

## 0. 验收前准备

1. 打开当前 Jarvis Desktop，确认窗口顶部显示 Core 已连接。
2. 向下滚动找到 **“手机闭环、复盘与 AI（T15–T20）”**。
3. 如需验收 T15，确保飞书机器人仍可用，`lark-cli` profile 为 `jarvis-t04`。
4. 准备一个不会影响真实工作的短测试时段。建议从当前时间后 2 分钟开始，持续 8–12 分钟。

若只走快速人工路径，约需 20–30 分钟。若坚持人工等待默认手机阈值和重复间隔，至少还需增加
40–60 分钟。

## 1. T19：硅基流动 AI、凭据和费用边界

入口：**手机闭环、复盘与 AI（T15–T20） → 自然语言 / AI**。

1. 在“硅基流动 API Key”中输入密钥，点击 **“保存到 Windows 凭据管理器”**。
2. “全局模型”选择 `Flash`，点击 **“应用模型”**。
3. 月度硬上限保持或设置为 `30` 元。
4. 在 **“普通对话（只回答文字，不会创建、修改或启动监督）”** 中输入
   `只回复：基础对话测试成功`，点击 **“发送基础对话”**。
5. 关闭并重新打开 Desktop，确认模型选择仍是 Flash。

通过指标：

- AI 状态显示 `SiliconFlow`、`DeepSeek-V4-Flash`、Key 末四位和本月费用/30 元上限。
- 请求期间能看到“云端请求处理中”或按钮的忙碌状态，之后得到真实文字回复。
- 普通对话不会产生候选卡，也不会在“Core 正式状态”中新建承诺。
- 重启后仍是 Flash；完整 Key 不出现在界面、SQLite、日志或截图中。

无需人工花费到 15/24/30 元。预警、硬上限、单次费用确认、预算预留和中断防重复收费均由自动化覆盖。

## 2. T20：自然语言生成并确认候选操作

入口仍是 **“自然语言 / AI”**，但使用上方的
**“安排或修改工作（生成确认卡）”**，不要使用下方的普通对话框。

### 2.1 口语时间和工具列表

先输入一条未来时段，避免把今天已经过去的时间误认为未来：

> 明天下午 1 点开始一个监督，一直到下午 5:40。我要进行交易复盘，要用到 Notion、TradingView 和浏览器。

1. 点击 **“生成候选操作”**。
2. 立即检查是否出现“正在生成候选操作，请稍后……”和进度条，且三个候选按钮暂时不可重复点击。
3. 检查候选摘要是否包含完整起止时间、交易复盘目标，以及 Notion、TradingView/`tradingview.com`、浏览器相关目标。
4. 此时向下看“Core 正式状态”，不应出现新承诺。
5. 点击 **“确认候选”**，再向下滚动到 **“Core 正式状态”**。

通过指标：

- 生成期间有明确忙碌反馈，不会让用户猜测是否卡住。
- 信息足够时生成一张候选卡；确认前零正式写入。
- 确认后只新增一条正式承诺，状态为 `Scheduled/等待开始`；到开始时刻后依次进入准备缓冲和监督中。
- 同一候选不能因双击重复成立。

### 2.2 缺少必要信息

输入 `帮我安排一个监督` 并生成候选。

通过指标：候选区明确列出缺少的时间、目标或电脑活动等具体项目，并提示如何补充；不能只显示笼统的
“请求失败”。补齐信息后可重新生成。

### 2.3 两个输入框的边界

把同一句安排文字再发到下方 **“普通对话”**。

通过指标：它只能返回解释性文字，不得生成候选、创建承诺或声称监督已经开始。

模板、有限重复安排、修订、取消、推迟和提前结束也走同一候选确认边界；这些分支已由自动化覆盖，
人工验收只需完成上面的一次真实创建主路径。

## 3. T15：飞书手机升级闭环

入口：**“飞书手机闭环”**。

1. 勾选“启用”，确认 CLI 与 profile，点击 **“保存并启动”**。
2. 在飞书中向机器人发送 `绑定 Jarvis`，直到 Desktop 显示消息和卡片监听均已就绪、用户已绑定。
3. 为快速人工验收，可在页面上方“监督默认设置”把“首次手机/手机重复/最多”临时设为
   `2 / 2 / 3`；严格默认验收则使用 `20 / 20 / 3`。
4. 创建并确认一条电脑型短承诺，明确一个相关软件/网站和一个分心软件/网站。
5. 承诺进入监督后持续停留在分心活动，等到手机阈值。
6. 检查飞书卡片和 Desktop 的 `MobileCardGrid`，再在手机点击一次 **“马上回去”**；切回相关活动并保持 2 分钟。
7. 再次进入分心活动，检查新一轮卡片序号是否从 `#1` 开始。

通过指标：

- 到阈值才发送卡片；隐私预览不显示软件、域名、窗口标题、文件名或正文。
- 卡片绑定当前承诺版本和本次偏离；恢复后旧卡变成只读结果。
- 恢复后新一次偏离从 `#1` 开始，不沿用上一次序号；最多发送配置的次数。
- “马上回去、误判、休息到、取消”都必须经过当前版本校验，旧卡不能再次操作。

快速人工路径只需真实验证一个按钮和旧卡失效；四按钮、最多三次、断线暂停、投递重试和重复回调由自动化覆盖。
T04 曾明确暂缓的 30 分钟断网、最小权限和额度证据不属于本轮 T15–T20 的通过条件。

## 4. T16：结束监督与承诺回顾

1. 在窗口最下方 **“Core 正式状态”** 选中刚才的测试承诺。
2. 可以等待自然到点，也可以在 **“承诺 / 每日复盘”** 点击 **“提前结束所选承诺”**。
3. 回到“Core 正式状态”检查阶段。
4. 保持该行选中，在“承诺 / 每日复盘”选择完成状态，输入一段可辨认的原始回顾文字，点击 **“提交回顾”**。

通过指标：

- 到点或提前结束后进入 `AwaitingReview/待回顾`，绝不能自动变成“已完成”。
- 提交后回顾列表显示已回答状态和所选完成情况；原始文字与结构化完成状态分开保存。
- 重启后回顾仍存在。

“30 分钟后回顾”和“跳过回顾”是另外两种明确选择；人工可任选一个额外短承诺抽查，三分支状态迁移由自动化完整覆盖。

## 5. T17：每日复盘

入口：**“承诺 / 每日复盘”** 下半部分。

1. 点击 **“现在开始”**，无需等到默认 23:00。
2. 阅读事实摘要和当前问题，在回答框输入内容，点击 **“回答并进入下一问”**。
3. 逐题完成；最后“明日调整”必须填写 1–3 项，每行一项。
4. 可另行点击一次“30 分钟后”或“60 分钟后”，确认界面显示已延期；不需要真的等待完整时间。

通过指标：

- 一次只出现一个问题，上一条原始回答被保存后才进入下一问。
- 事实摘要来自 Core 的承诺、分类、休息、提醒和已确认完成结果，不生成自律分数。
- 最后只接受 1–3 个明确调整；0 个或超过 3 个要显示具体错误。
- 完成后状态结束；重启不会重复开启同一场复盘。

23:00 自动邀请、工作中顺延、离线次日最多补问一次、30 分钟只追问一次属于真实时钟/故障场景，自动化已覆盖。

## 6. T18：周期复盘

入口：**“周期复盘”**。

1. 周期天数保持 `14`（也允许 7、28 或其他至少 2 天的有限值），点击 **“保存未来边界”**。
2. 点击 **“开始待处理周期复盘”**，可立即基于目前已有记录生成一次人工检查，不必真的等待 14 天。
3. 检查摘要中的计划项/分钟、可观察分钟、相关、分心、无法观察、休息、推迟/未回应等事实。
4. 检查“可追溯明细”能指回具体承诺和每日复盘。
5. 在“确认 1–3 个下周期重点”中每行填写一项，点击 **“确认重点”**。

通过指标：

- 只汇总当前周期边界内的事实，能看到来源，不生成自律分数或人格结论。
- 保存新周期配置只影响未来边界，不改写已完成周期。
- 只接受 1–3 个下周期重点，确认后刷新/重启仍保留。
