# T15–T20 手机闭环、复盘与自然语言操作

## 交付边界

这次纵切在既有 Core/Desktop/SQLite 架构内完成六项连续能力：

- 连续偏离达到承诺配置的手机阈值后，向已绑定的飞书私聊发送版本化升级卡；新卡、恢复、休息、修订、提前结束和到点结束都会使旧卡失效。
- 承诺到点或提前结束只进入“待回顾”，不自动推断完成；原始回顾和可选完成状态分别保存。
- 每日复盘默认本地 23:00，先展示 Core 的计划、活动分类、休息、提醒与已确认完成结果，再一次只问一个问题；支持主动提前开始、延后一次、跳过、30 分钟自动追问一次、Core 离线后次日最多补问一次，以及明确确认 1–3 个次日调整。到点仍有承诺在监督时，正常邀请顺延到该承诺结束；若期间 Core 退出，则下次启动只在本地列为待补，不补发过时手机邀请。
- 周期复盘默认 14 天，也支持 7 天、28 天和其他有限天数；只改变未来边界，逐项列出承诺/复盘来源以及可追溯的计划、观察、分类、休息、推迟和未回应事实，不生成自律分数。
- 云端 AI 通过一个窄适配器接入；凭据保存在 Windows 凭据管理器，SQLite 只保存末四位。每次请求记录用途、模型、令牌、价格版本、费用和成功状态，不记录完整提示词。
- 自然语言可以生成一次性承诺、从模板创建、有限重复安排、保存模板、修订、取消、推迟或提前结束候选。Core 先补默认值并校验，用户确认一次后才执行；取消会保留历史，推迟会结束当前监督并按剩余时长生成一条未来承诺。

## 权威边界

`CompanionModule` 对外只有命令分派、时间推进和快照读取三个入口。它内部协调飞书通道、承诺回顾、每日/周期复盘、AI 费用和自然语言候选；正式承诺仍只由 `SupervisionModule` 与同一 SQLite 数据库写入。

AI 不参与活动分类、偏离计时、提醒阈值、版本检查、冲突检查、权限或历史改写。AI 不可用、未配置或达到费用上限时，表单、按钮、模板、监督和复盘仍可使用；取消与按剩余时长推迟也有带原因、版本校验和二次确认的确定性按钮。每次调用在访问供应商前先按最坏估算占用预算，成功收到响应后再按实际 token 结算；进程在结果安全落库前中断时保留预留并拒绝自动重放，避免重复收费和越过硬上限。

自然语言确认采用一次性候选状态。确认前先将候选标为处理中，避免双击或并发请求重复成立；任何 Core 校验失败会恢复为待确认。应用在确认窗口中异常终止时不会自动重放可能已经执行的操作。飞书文本也复用同一候选：机器人先回复候选摘要，用户发送“确认候选”或“放弃候选”，不会让模型直接写正式状态。

飞书入站事件、监督按钮效果、文本回复、待发送卡片和旧卡失效都先记录到 SQLite，再执行外部投递；重投复用相同事件结果、卡片 ID 与消息幂等键。文本回复失败会保留在 outbox 并由 Core 重试；监督按钮即使在后续卡片状态写入失败也不会重复写监督历史。监听器只有在消息事件和卡片回调都出现 ready 标记且子进程仍存活时才报告就绪。

## 飞书实现说明

手机卡片使用 Card JSON 2.0。通知预览有全局“隐私/详细”两档且默认隐私：隐私档固定为“请解锁飞书查看详情”；详细档只尽可能显示平台允许的承诺摘要、计划时间、持续偏离时长和分类。两档都不显示软件名、网站、窗口标题、文件名、截图、输入内容、聊天正文、文档正文、回顾正文或个人记忆；系统或飞书关闭通知预览时，以平台设置为准。

解锁后的卡片提供“马上回去、误判、休息到、取消”四类确定性动作；新卡、恢复、休息、修订、取消、推迟、提前结束和到点结束都会把旧卡更新成只读结果。发送或更新暂时失败时保留待重试状态，不生成新的业务动作。

当前实现复用库存 `lark-cli` 的消息和事件能力。用户已经明确跳过 T04 剩余 Gate，因此本纵切不重新宣称 T04 的最小权限、额度或 30 分钟断网证据已经通过；特别是库存 CLI 监听卡片回调仍会要求它自身的消息只读 scope。这个限制不影响 T15–T20 的确定性 Core 设计，但正式发布前仍应由安装/权限任务收口。

## 硅基流动 DeepSeek 当前配置

2026-08-15 按用户确认改为统一使用硅基流动账号与密钥。模型由 Desktop 的全局选项明确选择并持久化：默认所有用途调用 `deepseek-ai/DeepSeek-V4-Flash` 并关闭思考模式；用户需要时可把所有用途切换为 `deepseek-ai/DeepSeek-V4-Pro`。请求固定发送到 `https://api.siliconflow.cn/v1/chat/completions`，不会把硅基流动密钥发送到 DeepSeek 官方端点，也不会由模型自行升级。

当前人民币单价为：Flash 缓存命中输入 0.02 元、普通输入 1 元、输出 2 元/百万 tokens；Pro 分别为 1 元、12 元和 24 元/百万 tokens。来源：

- [硅基流动 Chat Completions API](https://api-docs.siliconflow.cn/docs/api/chat-completions-post)
- [硅基流动模型与价格](https://siliconflow.cn/pricing)
- [硅基流动隐私政策](https://api-docs.siliconflow.cn/docs/legals/privacy-policy)

旧版已经保存到 `Jarvis/AI/deepseek` 凭据槽的密钥会被兼容读取；新保存使用 `Jarvis/AI/siliconflow`。两者都不进入 SQLite、日志或备份。

Jarvis 本机月度硬上限默认为 30 元，15 元和 24 元显示预警；单次估算超过 1 元必须再次确认。达到上限后不自动充值、不自动切换供应商；只有用户在 Desktop 明确确认提高硬上限后才恢复请求。Provider、模型、费用、凭据末四位和云端请求处理中状态均可见。

自然语言候选区会在请求期间立即显示“正在生成候选操作”，并禁用重复生成、确认和放弃按钮。模型或 Core 发现必要信息缺失时，会在输入框下方列出具体缺失项和修改提示，不再只把错误塞进全局状态。普通对话区明确标记为只返回文字，不会创建、修改或启动监督。候选提示词覆盖自然口语的同日时间段、只需一个投入/成果目标，以及“要用到”的软件/网站列表；例如“下午 1 点到 5:40 做交易复盘，要用 Notion、TradingView 和浏览器”会先生成候选卡，确认后才进入正式监督状态。
